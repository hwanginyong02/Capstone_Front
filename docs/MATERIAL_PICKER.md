# 재료 고르기와 입력 흐름 개편

2026-10-15 디자인 세션에서 정한 것. 기준 코드는 dev 브랜치(f04eae0, PR #53 머지 시점)와 docs/COMPOSER_COMPONENTS.md, 재료 레지스트리(src/data/reportComposer.ts)다.

참고 파일: `docs/imports/material-picker-prototype.dc.html` — 재료 고르기 프로토타입 소스. 새로 디자인한 것은 **작업 유형과 재료 고르기 두 화면뿐**이다. 프로토타입 안의 재료 입력·확인과 생성 화면은 흐름을 눌러 보기 위한 임시 화면이라 구현 대상이 아니다(5절). 프로토타입 안의 `data()`는 카드·필드·한국어 이름·설명 문구의 초안이고, `renderVals()`는 저장 규칙(7절)의 동작 예시다.

## 1. 전체 흐름

작업 유형 → 재료 고르기 → 재료 입력(카드 순서대로) → 확인과 생성

- 재료 고르기는 성적서 구성 화면(/app/composer)을 대신한다.
- 입력 순서는 사용자가 정하지 않는다. 카탈로그 순서가 곧 입력 순서다. *(§11로 대체됨 — 입력 순서는 사용자가 다이어그램에서 정한다. 카탈로그 순서는 처음 순서다)*
- "평가만 하고 끝내는" 동선은 없다.

## 2. 카드 구조 — 9장을 대분류 4개로 묶는다

| 대분류 | 카드 (레지스트리 id) | 구분 |
|---|---|---|
| 의뢰 정보 | 의뢰자 정보 ③ (clientInfo) | 필수 |
| 모델 | 평가 대상 모델 ④ (model) | 필수 |
| 모델 | 모델 설정과 실행 환경 ⑨ (modelEnv) | 선택 카드 |
| 데이터 | 평가 데이터 ① (evalData) | 필수 |
| 데이터 | 학습 데이터 ⑥ (trainingData) | 선택 카드 |
| 데이터 | 테스트 데이터 ⑦ (testData) | 선택 카드 |
| 데이터 | 정답 라벨 ⑧ (groundTruth) | 선택 카드 |
| 평가 기준 | 평가 관점 ⑤ (perspective) | 필수 |
| 평가 기준 | 지표와 합격 기준 ② (metrics) | 필수 |

카드 안의 필드는 레지스트리를 그대로 따른다.

## 3. 입력 순서 — 카드 순서로 바꾼다

의뢰자 정보 → 평가 대상 모델 → (모델 설정과 실행 환경) → 평가 데이터(업로드, 컬럼 매핑) → (학습 데이터) → (테스트 데이터) → (정답 라벨) → 평가 관점 → 지표와 합격 기준 → 검증 → 확인과 생성

*(§11로 대체됨 — 위 순서는 처음 순서다. 사용자가 레인과 카드 순서를 바꿀 수 있고, "지표와 합격 기준·학습 데이터는 평가 데이터 뒤"라는 규칙만 지킨다. 검증과 확인과 생성은 늘 맨 끝이다)*

- 지금은 "백엔드가 지표 목록 없이 검증·평가 요청을 받지 않는다"는 이유로 파일 → 지표 → 매핑 → 검증이 앞에 있다(WORKFLOW_REDESIGN §2.1, §11). 이 순서를 버리므로 다음을 함께 바꾼다.
  - 컬럼 매핑이 지표에 기대지 않게 한다. 매핑을 먼저 하고, 지표 화면에서 매핑된 컬럼으로 계산할 수 없는 지표(예: 확률 컬럼 없이 AUROC, AUPRC, Log Loss)는 처음부터 비활성으로 두고 이유를 한 줄 붙인다. "지표 제외" 처리는 없앤다.
  - 검증은 지표와 합격 기준 뒤, 확인과 생성 앞으로 옮긴다. 백엔드는 바꾸지 않는다.
  - 평가 관점은 지표 바로 앞이라 지표 추천은 그대로 동작한다.
- 합격 목표값은 지표와 합격 기준에서 평가 전에 받는다. 결과와의 비교는 성적서에서 확인한다.
- 학습 데이터의 클래스별 데이터 양은 평가 데이터의 클래스 목록이 필요하다. 평가 데이터가 앞이라 지켜진다.

## 4. 재료 고르기 화면 구조 (3단)

- 왼쪽: 대분류 네모 카드 4개. 고르면 그 아래에 카드 목록이 나온다. 목록은 테두리 하나 안에 두고 줄마다 구분선을 긋는다. 필수 카드에는 "필수"라는 글자를 붙인다.
- 가운데: 고른 카드의 필드. 섹션은 필수 / 권장 / 선택 / 조건부. 필수는 체크박스 없이 글자만, 권장과 선택은 체크박스(기본 꺼짐), 조건부는 조건 문구와 함께 보여준다. 아래에 저장 버튼.
- 오른쪽: 입력 순서. 필수 카드와, 항목을 하나 이상 골라 저장한 선택 카드가 순서대로 나온다. 라벨 없음. 아래에 "필수 5개 중 N개 저장"과 이전/다음.

*(§11로 대체됨 — 왼쪽 재료 목록(대분류 → 카드 → 항목 나무), 가운데 4열 다이어그램, 하단 현황 바다. 대분류 네모 카드·오른쪽 입력 순서 패널·저장 버튼은 없앴다)*

## 5. 재료 입력 화면 — 기존 화면을 쓴다

재료 입력과 확인과 생성은 새로 디자인하지 않는다. 지금 있는 화면을 쓰고, 세 가지만 바꾼다.

1. 디자인 시스템(10절)과 한국어 문구(8절)를 입힌다.
2. 재료 고르기에서 체크하지 않은 권장·선택 필드는 숨긴다. 필수 필드는 늘 보인다.
3. 화면 순서를 3절의 카드 순서로 바꾼다.

| 카드 | 지금 화면 (파일) | 지금 그 화면이 받는 것 | 바꿀 것 |
|---|---|---|---|
| 의뢰자 정보 ③ | Details (/report/:id/issue-info, pages/report/ReportInfo.tsx) | ③ 전체, ④ 모델 용도, ② 합격 기준·핵심 지표 | ③만 남기고 ④·②는 각자 카드 화면으로 옮긴다 |
| 평가 대상 모델 ④ | 업로드 화면(모델명·버전)과 Details(모델 용도)에 나뉘어 있음 | — | 한 화면으로 모은다 |
| 모델 설정과 실행 환경 ⑨ | Model info (/report/:id/model-env, pages/report/ModelEnv.tsx) | ⑨ 전체 | 순서만 앞으로 |
| 평가 데이터 ① | Evaluation File (pages/DataUpload.tsx) + Column mapping (pages/ColumnMapping.tsx) | 파일, 매핑, 양성 클래스, 결정 임계값 | 매핑이 지표에 기대지 않게(3절) |
| 학습·테스트 데이터, 정답 라벨 ⑥⑦⑧ | Data info (/report/:id/data-info, pages/report/DataInfo.tsx) | 켠 카드만 카드 순서대로 | 그대로 *(§11로 대체됨 — 카드마다 한 단계: /app/training-data, /app/test-data, /app/ground-truth)* |
| 평가 관점 ⑤ | Metrics 화면 맨 위 (pages/TestItems.tsx) | ⑤ 전체 | 지표 바로 앞 단계로 |
| 지표와 합격 기준 ② | Metrics (지표, β, 선택 이유) + Details의 합격 기준 표 | — | 합격 기준 표를 지표 쪽으로 합치고, 계산할 수 없는 지표는 비활성 |
| (검증) | Validation (pages/DataValidation.tsx) | 검증 후 run 저장 | 지표와 합격 기준 뒤로 |
| 확인과 생성 | Result (/report/:id) | 평가 실행, AI 서술, 성적서 | 빠진 권장 항목 안내를 앞에 둔다 |

- Details, Data info, Model info는 지금 run id가 있어야 열리는 경로(/report/:runId/...)다(src/data/workflowSteps.ts의 runScoped). run은 검증에서 만들어지고, 이 화면들이 검증보다 앞으로 오므로 /app/* 경로로 옮긴다. 값은 지금처럼 워크플로 저장소에 둔다.

## 6. 표준 보고 항목 규칙 — 항목별 체크, 기본 꺼짐

- 지금은 "선택 카드를 켜면 그 안의 표준 보고 항목은 필수, 모르면 모름"이다(COMPOSER_COMPONENTS "결정 사항과 열린 결정"). 이것을 바꾼다.
- 선택 카드(⑥~⑨) 안의 표준 보고 항목(레지스트리의 required)은 "권장"으로 보여주고 항목마다 체크한다. 기본은 꺼짐. 끈 항목은 성적서에 "제공되지 않음"으로 찍히고, 확인과 생성 단계에서 빠진 권장 항목으로 알린다.
- 권장 항목은 재료 한 줄 단위로 묶어 체크한다(예: 실행 환경의 OS, CPU, GPU, 메모리, 소프트웨어). 선택 항목은 하나씩 체크한다.
- 체크해서 받기로 한 권장 항목은 입력 화면에서 비울 수 없고, 모르면 "모름"을 고른다(지금 규칙과 같다).

## 7. 저장 규칙 (재료 고르기)

*(§11로 대체됨 — 저장 단계는 없다. 넣고 빼는 즉시 반영되고, 필수 카드는 처음부터 들어가 있어 다음을 막지 않는다. 아래는 종전 기록)*

- 저장 = 그 카드에서 무엇을 받을지(체크 상태)를 확정하는 것. 실제 값 입력이 아니다.
- 저장하면 카드 줄과 오른쪽 입력 순서의 카드가 저장 표시(강조 배경 + 체크)로 바뀐다. 대분류 안의 필수 카드가 모두 저장되면 대분류 카드도 저장 표시로 바뀐다.
- 필수 카드를 하나라도 저장하지 않고 다음을 누르면 넘어가지 않고, 저장하지 않은 필수 카드 이름을 오류로 보여준다.
- 선택 카드를 저장하지 않으면 그 카드는 빼고 진행한다. 아무것도 체크하지 않고 저장한 선택 카드는 "넣지 않기로 확정"이다.
- 저장하지 않고 다른 카드로 가도 체크는 화면에 남지만 반영되지 않는다. 다음을 누르면 마지막으로 저장한 내용이 적용된다. 저장한 뒤 체크를 바꾸면 "저장하지 않은 변경이 있어요"를 보여준다.

## 8. 필드 표시와 문구

- 재료 고르기에서 필드는 하나씩 쪼개 보여준다(예: 회사명, 대표자, 사업자등록번호를 따로).
- 필드 이름은 검정, 그 필드만의 짧은 설명은 회색, 형식(텍스트, CSV/JSON 파일, 하나 선택 등)은 이름 오른쪽에 회색으로.
- 필드 설명 문구는 초안이다(프로토타입 `data()`의 desc). 검토가 필요하다.
- **앱 화면 문구를 전부 한국어로 바꾼다.** 지금은 기존 테스트가 영문 문자열을 찾고 있어 영어로 통일해 두었다(WORKFLOW_REDESIGN §6.3). 바꿀 때 테스트도 함께 고친다.
- 선택지 **저장값은 영어 그대로 둔다.** 화면에 보이는 이름만 한국어로 바꾼다. 성적서에 찍히는 이름은 지금처럼 reportLabels를 쓴다. 저장된 데이터를 옮기지 않는다.

## 11. 다이어그램으로 고르고 순서 정하기 (2026-10-16 팀 피드백 반영)

PR #54 이후 팀 피드백: 화면이 각 필드 설명을 보여 주는 데 그치고, 사용자가 직접 구성하며 상태를 확인하는 흐름이 아니었다. 다이어그램이 오른쪽에 작게 있었고, 순서를 바꿀 수 없었으며, 필수 카드까지 저장을 눌러야 반영됐다. 아래가 그 결정이다. §1·§3·§4·§7의 해당 부분을 대체한다.

### 11.1 화면 구조

- **왼쪽 재료 목록**: 대분류 → 카드 → 항목(권장·선택)을 들여쓰기와 연결선으로 보이는 나무다. 대분류에 "카드 n장" 같은 수 문구는 달지 않는다. 카드를 펼치면 카드 설명, 늘 들어가는 필수 항목 수, 고를 항목이 나온다. 필드 설명은 이름에 마우스를 올렸을 때 보인다 — 설명이 화면의 주인공이 아니다.
- **가운데 다이어그램**: 대분류 4열 레인이다. 들어간 카드가 레인마다 노드로 보이고, 노드 머리의 번호가 입력 순서다. 노드에는 받기로 한 항목이 칩으로 붙는다. 필수·조건부는 "필수 n"으로 접어 보이고, 권장·선택 칩은 ×로 뺀다. 권장이 있는 카드는 "권장 x/y"를 보인다. "항목 고르기"로 펼치면 그 카드의 항목을 클릭 한 번으로 넣고 뺀다.
- **하단 바**: 필수 카드 수, 권장 들어간 수/전체, 선택 들어간 수/전체, 품질 단계, 그리고 표준까지 남은 권장 항목 경고. "빠진 항목 보기"로 펼쳐 바로 넣는다. 이전·다음도 여기 있다.
- **추천 세트**: 머리 오른쪽의 최소 / 표준 / 상세. 적용하면 항목을 통째로 바꾸고 "되돌리기"를 보인다. 지금 고른 것이 세트와 똑같을 때만 그 버튼이 눌린 모양이다.

코드: `pages/MaterialPicker.tsx`, `components/material-picker/`(`PickPalette`, `PickDiagram`, `DiagramLane`, `CardNode`, `PickStatusBar`, `PickSetToggle`, `dnd.ts`).

### 11.2 넣고 빼기 — 바로 반영

- 저장 단계는 없다. 넣고 빼는 즉시 스토어(`materialPicks`)에 들어가고 다이어그램에 보인다.
- 필수 카드와 그 안의 필수·조건부 필드는 처음부터 들어가 있다. 재료 고르기에 들어오면 필수 카드의 키를 빈 배열로 채운다(`initRequiredPicks`) — 고르지 않은 선택 항목(홈페이지·팩스)을 입력 화면이 묻지 않게 한다.
- 선택 카드를 끌어 놓거나 ＋를 누르면 그 카드의 **권장 항목이 모두 든 채로** 들어간다. 카드를 싣겠다는 뜻이므로 표준 보고 항목을 빠짐없이 받는 쪽을 기본으로 둔다. 권장이 없는 카드면 선택 항목이 모두 든다.
- 항목을 끌어 놓거나 ＋를 누르면 그 항목이 원래 카드에 들어가고, 카드가 빠져 있었으면 카드도 들어간다.
- 선택 카드는 항목이 하나라도 있으면 들어간 것이다(§7 규칙 유지). 마지막 칩을 빼거나 노드의 ×를 누르거나 노드를 재료 목록으로 끌어 오면 빠진다.
- 새로 들어간 선택 카드는 그 레인 맨 아래로 간다.

### 11.3 입력 순서

- 순서 = **레인 순서 + 레인 안 카드 순서**다. 왼쪽 레인부터, 레인 안에서는 위부터 읽은 것이 입력 순서다. 대분류끼리는 섞이지 않는다.
- 레인 머리를 좌우로 끌거나 ◀▶, 노드를 위아래로 끌거나 ▲▼로 바꾼다. 모든 끌기에는 같은 일을 하는 버튼이 있다(HTML5 끌어 놓기는 키보드로 할 수 없다).
- 스토어는 평탄한 카드 목록 하나(`cardOrder`)로 든다. 넣지 않은 선택 카드도 자리를 갖는다.
- **깨면 놓지 못하는 규칙**(`ORDER_RULES`). 어기는 자리에 놓으면 원래 자리에 두고 이유를 한 줄로 보인다.
  1. 지표와 합격 기준은 평가 데이터 뒤 — 컬럼 매핑 결과로 계산할 수 있는 지표를 정한다. 레인으로 보면 '평가 기준' 레인은 '데이터' 레인 뒤에만 온다.
  2. 학습 데이터는 평가 데이터 뒤 — 클래스별 데이터 양을 평가 데이터의 클래스 목록으로 받는다.
- **알리기만 하는 권고**(`ORDER_HINTS`): 평가 관점이 지표보다 뒤면 지표 추천을 받을 수 없다고 다이어그램 위에 알린다.
- 검증과 확인과 생성은 카드가 아니라 순서와 무관하게 늘 맨 끝이다.
- 단계 목록은 들어간 카드를 이 순서대로 카드의 `steps` 로 펼친 것이다(`buildStepList(selection, order)`). ① 평가 데이터는 업로드와 컬럼 매핑 두 단계가 된다.

### 11.4 데이터 카드 단계 분리

- ⑥ ⑦ ⑧ 을 묶던 "데이터 정보" 단계를 카드마다 한 단계로 나눴다(`/app/training-data`, `/app/test-data`, `/app/ground-truth`). 사용자 순서에서는 셋이 떨어질 수 있다(예: 테스트 데이터 → 평가 데이터 → 학습 데이터).
- 단계 수는 최소 8, 전체 12다.
- `/app/data-info` 옛 링크는 넣은 첫 데이터 카드의 단계로, 없으면 재료 고르기로 보낸다.
- persist v13: `cardOrder` 를 카탈로그 순서로 채우고, 진행 표시의 `"dataInfo"` 는 넣어 둔 데이터 카드 단계로 옮긴다.

### 11.5 품질 단계와 추천 세트

| 단계 | 받는 것 | 성적서 |
|---|---|---|
| 최소 | 필수만 | 나온다. 표준 보고 항목(권장)이 "제공되지 않음"으로 찍힌다 |
| 표준 | 최소 + 모든 선택 카드의 권장 항목 전부 | **충분한 품질의 기준선.** 표준 보고 항목을 모두 갖춘다 |
| 상세 | 표준 + 모든 선택 항목 | AI 서술이 기댈 근거가 가장 많다 |

- 지금 단계는 고른 것에서 계산한다(`pickTier`): 권장을 다 받으면 표준, 선택까지 다 받으면 상세, 그 밖은 최소.
- 하단 바는 표준에 못 미치면 "표준까지 권장 k개"와 "제공되지 않음" 경고를 보인다.
- 받기로 한 권장 항목은 입력 화면에서 비울 수 없고 모르면 "모름"을 고른다(§6 그대로).

### 11.6 단계 표시줄

- 입력 화면의 단계 표시줄 맨 위에 "재료 고르기" 버튼을 둔다. 순서와 넣을 항목을 언제든 다이어그램에서 다시 본다.
- 첫 단계의 이전은 재료 고르기로 간다. 첫 단계가 순서에 따라 달라지므로 화면이 아니라 `useStepFlow` 가 정한다.
