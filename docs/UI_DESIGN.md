# UI 설계 — 분류 유형 아이콘화 및 분리

> **범위**: 세 분류 유형(이진·다중 클래스·다중 레이블)을 **아이콘으로 구분되는 독립
> 진입점**으로 분리한 화면 설계. 흐름·화면 순서는 `docs/MATERIAL_PICKER.md` §12,
> 색상·타이포 등 디자인 시스템은 `docs/imports/colors.md` 와 `docs/MATERIAL_PICKER.md` §10.
> 화면 문구는 한국어로 정리했다(유형 이름은 `src/data/evaluationData.ts` 의 `TASK_TYPE_LABELS_KO`).

---

## 1. 무엇을 고쳤나

세 유형은 **이미 내부적으로 완전히 다르게 처리된다.** `data/evaluationData.ts` 하나만
봐도 `task_type` 이 가르는 것이:

| 가르는 것 | 근거 |
|---|---|
| 노출 지표 | `getAvailableMetrics` — multilabel 은 M1·M11·M12·M13 이 아예 없다 |
| 요구 컬럼 | `REQUIRED_COLUMNS_BY_METRIC` — task 별로 표가 따로 있다 |
| 매핑 가능 역할 | `MAPPABLE_ROLES_BY_TASK` — `score` / `prob_class_*` / `prob_label_*` |
| 예측 파생 방식 | binary=임계값, multiclass=argmax, multilabel=레이블별 임계값 |
| 임계값 입력 형태 | 스칼라 vs 컬럼별 객체 |

백엔드도 `evaluation/metrics/{binary,multiclass,multilabel}.py` 로 파일이 갈려 있다.

**차이는 전부 구현돼 있다. 화면에만 없다.**

이 설계 전에는 세 유형이 하나의 공용 화면 안에서 조건문으로만 갈렸다. 사용자 눈에 보이는 건:

1. 기본 정보 화면 세 번째 카드 맨 아래의 라디오 카드 3장 — **필수 입력 12개 중 마지막**
2. 그 뒤로는 **아무것도 없었다** — 머리(`AppHeader`)는 "ML 성능평가" 고정 글자뿐이고,
   단계 표시는 숫자만 있는 가로 탭이었다(지금은 오른쪽 세로 단계 표시줄 `StepRail`)

앱 전체를 가르는 분기점이 폼 필드 하나와 같은 무게로 놓여 있었고, 고르고 나면 사라졌다.

**→ 없는 기능을 만든 게 아니라 이미 있는 차이를 드러낸 것이다.**

---

## 2. 아이콘 ★

이 문서의 핵심이다. **아이콘 자체가 세 유형의 차이를 설명해야 한다** — 텍스트 설명을
장식하는 그림이 아니다.

### 2.1 설계 원칙

셋이 **같은 도형(원)** 을 쓰고, **개수와 채움만** 다르게 한다. 그래야 나란히 놓았을 때
차이가 도형에서 바로 읽힌다.

| 유형 | 도형 | 읽히는 뜻 |
|---|---|---|
| 이진 | 원 2개 중 1개 채움 | 후보가 **둘**, 답은 **하나** |
| 다중 클래스 | 원 4개 중 1개 채움 | 후보가 **여럿**, 답은 **하나** |
| 다중 레이블 | 원 4개 중 3개 채움 | 후보가 **여럿**, 답도 **여럿** |

"채움 = 이 샘플에 배정된 것"이라는 규칙이 셋 모두에서 일관되게 성립한다.

### 2.2 마크업

`lucide-react` 에 다중 레이블을 뜻하는 아이콘은 없어서 인라인 SVG 로 직접 만들었다
(`src/components/task-type/TaskTypeIcon.tsx`). 40×40 상자에 반지름 7 의 원을 놓는다.

- `currentColor` 만 쓴다 → 선택 시 부모의 `text-primary` 를 그대로 따라간다. 상태별
  색을 따로 관리하지 않는다
- multiclass 와 multilabel 이 **같은 2×2 격자**를 쓰는 게 중요하다. 격자가 다르면
  "채운 개수의 차이"가 아니라 "다른 그림"으로 읽힌다
- `aria-hidden` — 의미는 옆의 제목 텍스트가 전달한다. 스크린리더에 도형을 읽힐 이유가 없다

### 2.3 "장식 아이콘 금지" 규칙과의 관계

충돌하지 않는다. 그 규칙이 막는 것은 **의미 없이 붙는 그림**이다. 여기 아이콘은
채운 개수가 곧 분류 규칙이라 **정보를 지닌 도형**이다. 이 문단을 근거로 남긴다.

## 3. 진입 화면 (`/app`)

```
┌───────────────────────────────────────────────────────────┐
│   (제목: 어떤 분류 모델을 평가하나)                            │
│   (부제: 선택에 따라 지표·필요 컬럼·검증 규칙이 달라진다)          │
│                                                           │
│   ┌───────────┐   ┌───────────┐   ┌───────────┐          │
│   │   ○ ●     │   │  ● ○      │   │  ● ●      │          │
│   │           │   │  ○ ○      │   │  ○ ●      │          │
│   │           │   │           │   │           │          │
│   │  이진 분류  │   │ 다중 클래스 │   │ 다중 레이블 │          │
│   │  (설명 1줄) │   │ (설명 1줄) │   │ (설명 1줄)  │          │
│   │           │   │           │   │           │          │
│   │  예: …     │   │  예: …     │   │  예: …     │          │
│   └───────────┘   └───────────┘   └───────────┘          │
└───────────────────────────────────────────────────────────┘
```

**레이아웃**
- 그리드 `md` 이상 3열 / 미만 1열
- 카드는 `src/components/task-type/TaskTypeSelect.tsx` 에 있다 —
  선택 `border-primary` + `bg-primary-subtle`, 비선택 `border-border` + hover 때 `border-border-strong`
- **아이콘은 카드 상단에 크게(40px)** 놓는다. 세 카드를 훑을 때 도형이 먼저 눈에 들어와야 한다

**동작**
- **카드 클릭 = 즉시 다음 화면.** 라디오 인디케이터를 넣지 않는다 — 선택 상태를 보여줄
  시간이 없고, 넣으면 "고르고 → 다음 버튼" 두 동작이 된다
- 하단 Action Bar 없음
- 단계 표시줄(`StepRail`) 숨김 — 아직 워크플로우에 들어가기 전이다

**각 카드가 담는 3줄**
1. 유형 이름 — "이진 분류 / 다중 클래스 분류 / 다중 레이블 분류". 화면과 성적서·AI 서술이 같은 한 벌을 쓴다
   (`TASK_TYPE_LABELS_KO`, MATERIAL_PICKER.md §12.6). 위 그림의 줄인 이름은 칸 폭 때문이다
2. 한 줄 설명 — 세 카드가 **같은 문장 골격**을 쓴다. 바뀌는 부분만 다르게 해서
   나란히 읽으면 차이가 드러나게 한다
3. 구체 예시 한 줄 — 추상 설명만으로는 다중 클래스/다중 레이블이 구분되지 않는다

> 문구는 한국어로 확정했다(설명은 `TASK_TYPE_DESCRIPTIONS_KO`). **"세 줄, 같은 골격"** 구조를
> 지킨 이유: 옛 영문 문구는 세 번째만 문장 구조가 달라서(`"Multiple labels can be assigned"` 만
> 수동태) 가장 헷갈리는 유형의 설명이 가장 안 읽혔다.

## 4. 유형 배지 — 고른 뒤에도 보이게

분리의 나머지 절반이다. 진입 화면만 만들고 끝내면 **고른 순간 다시 안 보인다.**

`layout/components/AppHeader.tsx` 로고 오른쪽:

```
[◧] ML 성능평가                  분류 유형 [◈ 다중 클래스 분류]
    ISO/IEC 4213 기반
```

- §2 아이콘을 **16px 로 축소해 재사용** — 진입 화면에서 고른 그 도형이 그대로 따라온다.
  이 재사용이 "내가 고른 것"과 "지금 하는 것"을 잇는다
- `components/ui/badge.tsx` 의 `variant="secondary"` 모양을 버튼에 입힌다. 왼쪽에 "분류 유형" 글자, 툴팁에 유형 설명
- 워크플로우 밖(`AppShell`·랜딩·워크스페이스)에서는 숨긴다
- **클릭 시 유형 변경 가능. 단 확인을 받는다** — `useWorkflowStore` 의 `setTaskType`
  은 유형 선택 뒤의 입력(고른 지표·올린 데이터·컬럼 매핑·진행 표시 등)을 **전부 비운다**.
  경고 없이 날리면 안 되므로, 마친 화면이 하나라도 있으면 `window.confirm` 으로 묻는다
