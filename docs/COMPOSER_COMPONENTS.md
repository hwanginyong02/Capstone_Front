# 성적서 구성 컴포넌트 설계

Oct 3, 2026 · @인용

## 개요

> **MATERIAL_PICKER.md로 대체됨** (§1·§4·§8) — 선택 카드는 켜고 끄지 않고 항목을 골라 저장한다(§11로 대체됨 — 저장 없이 넣고 빼는 즉시 반영된다. 입력 순서는 다이어그램에서 사용자가 정한다). 흐름은 작업 유형 → 재료 고르기 → 재료 입력(카드 순서) → 확인과 생성이고, 재료 고르기는 필드를 하나씩 쪼개 이름·설명·형식으로 보여 준다. 아래는 종전 기록.

성적서 구성 화면은 카드 9개(필수 5개, 선택 4개)로 이루어지며, 사용자는 선택 카드를 켜고 끄는 것만으로 자신만의 시험성적서를 구성한다. 지도교수 피드백에 따라 단계별로 받던 입력을 컴포넌트로 묶어, 한 화면에서 고르고 "다음"을 누르면 고른 카드의 입력 단계만 만들어진다.

전체 흐름은 다음과 같다.

1. 분류 유형 선택 (이진 / 다중 클래스 / 멀티레이블)
2. 성적서 구성 (카드 고르기)
3. 평가 입력 (파일, 지표, 컬럼 매핑)과 검증 *(MATERIAL_PICKER.md로 대체됨, §1·§3 — 입력은 카드 순서대로 받고, 검증은 확인과 생성 바로 앞이다)*
4. 성적서 입력 (의뢰자 정보, 고른 선택 카드만 카드 순서대로)
5. 평가 실행, 성적서 생성과 발급

각 카드에는 네 가지만 보여준다.

- **설명**: 이 카드가 무엇인지 한 문장
- **필드**: 카드 안에서 입력할 항목
- **입력 방식**: 실제 값을 예시로 보여준다 (예: `전문가 수동 / 크라우드소싱 / …`)
- **구분**: 필수 / 보고 / 선택 / 조건부

성적서 위치와 AI 전달 여부는 개발자용 정보라 카드에 보이지 않고, 코드의 재료 레지스트리에만 둔다.

## 카드를 나눈 기준과 구분 규칙

카드와 필드는 세 가지 기준으로 나눴다.

- 성적서의 **절이나 표가 생기고 사라지면 카드**, 같은 칸의 **내용만 바뀌면 필드**로 둔다.
- 업로드 파일 안의 컬럼(확률 점수, 응답시간 등)은 따로 줄 수 없으므로 **평가 데이터 카드에서 파일로 받고**, 컬럼 매핑 단계에서 확인한다.
- 기본값이 있거나 있으면 좋은 정도의 항목은 **더보기**로 접어 카드에 보이는 필드를 줄인다.

구분은 네 가지다.

> **MATERIAL_PICKER.md로 대체됨** (§6) — 재료 고르기의 구분은 필수 / 권장 / 선택 / 조건부다. "필수 (표준 보고)"는 **권장**이 되어 항목마다 체크하고 기본은 꺼짐이다. 끈 항목은 성적서에 "제공되지 않음"으로 찍힌다. 아래 표는 종전 규칙이다.

| 구분 | 뜻 | 비우면 |
| --- | --- | --- |
| 필수 | 성적서가 성립하는 데 꼭 필요한 값 (재료 선택 점검 1층) | 다음 단계로 진행할 수 없다 |
| 필수 (표준 보고) | TS 4213이 성적서에 적으라고 요구하는 항목 (재료 선택 점검 2층). 카드를 켜면 반드시 입력해야 하고, 모르면 "모름"을 고른다 | 다음 단계로 진행할 수 없다. "모름"을 고르거나 카드를 끄면 성적서에 "제공되지 않음"으로 찍힌다 |
| 선택 | 성적서를 풍부하게 하는 값 | 그 칸이 빠진다 |
| 조건부 | 특정 조건에서만 나타나고, 나타나면 필수 | 조건에 따라 다르다 |

선택지에서 "모름"을 고르면 "제공되지 않음"으로 센다. 단, 수집 환경 차이(채널 효과)의 "알려진 것 없음"은 원문이 요구하는 답이라 제공된 것으로 센다. 작업 유형에 원래 없는 항목은 카드에서 숨기고 성적서에는 "해당 없음"으로 적는다.

## 카드 9개 한눈에 보기

필수 카드 5개는 잠겨 있어 뺄 수 없고, 선택 카드 4개는 끄면 그 안의 표준 보고 항목이 "제공되지 않음"으로 찍힌다. *(MATERIAL_PICKER.md로 대체됨, §2·§6 — 카드 9장은 대분류 4개로 묶이고, 선택 카드는 권장 항목을 골라 저장해야 들어간다)*

| 카드 | 구분 | 설명 | 적용 유형 |
| --- | --- | --- | --- |
| ① 평가 데이터 | 필수 | 예측 결과 파일 올리기 | 전부 |
| ② 지표와 합격 기준 | 필수 | 평가 지표와 목표 기준 | 전부 |
| ③ 의뢰자 정보 | 필수 | 성적서를 받는 회사와 용도 | 전부 |
| ④ 평가 대상 모델 | 필수 | 모델 이름과 쓰임새 | 전부 |
| ⑤ 평가 관점 | 필수 | 이 모델에서 무엇을 중요하게 볼지 | 전부 (필드는 유형별로 다름) |
| ⑥ 학습 데이터 | 선택 | 모델을 훈련할 때 쓴 데이터 | 전부 |
| ⑦ 테스트 데이터 | 선택 | 성능을 잰 테스트 데이터의 출처 | 전부 |
| ⑧ 정답 라벨 | 선택 | 테스트 데이터의 정답을 누가, 어떻게 붙였는지 | 전부 |
| ⑨ 모델 설정과 실행 환경 | 선택 | 모델 설정값과 실행한 컴퓨터 | 전부 |

재료 목록의 사용자 입력 항목(1\~8절)은 모두 이 9개 카드 중 하나에 들어간다. 시스템 계산 값(9절)은 사용자가 입력하지 않으므로 카드가 없고, 성적서 관리 항목(10절: 발급 확인, 정정 사유, 워크스페이스)은 성적서 내용이 아니라서 발급 단계에 둔다.

## 카드별 상세

각 카드는 설명 한 줄과 필드 표로 구성된다. 필드 이름은 명사로 쓰고, 뜻이 덜 전해지는 필드는 입력 화면에서 한 줄 도움말을 붙인다. 선택 카드(⑥\~⑨)의 "필수"는 카드를 켰을 때 필수라는 뜻이며, 모르면 "모름"을 고른다. *(MATERIAL_PICKER.md로 대체됨, §6 — 선택 카드의 "필수"는 권장이고, 체크한 항목만 입력 화면에서 비울 수 없다)*

### ① 평가 데이터 (필수)

예측 결과 파일 올리기.

| 필드 | 입력 예시 | 구분 |
| --- | --- | --- |
| 결과 파일 | `predictions.csv` 업로드 (CSV·JSON, 20 MiB 이하) | 필수 |

카드에 **예시 파일 보기** 버튼을 두고, 누르면 선택한 분류 유형의 예시를 보여준다. 컬럼 매핑, 양성 클래스, 결정 임계값은 "다음" 이후 컬럼 매핑 단계에서 처리한다. *(MATERIAL_PICKER.md로 대체됨, §4 — 재료 고르기에는 보기 버튼이 없다. 예시 파일은 업로드 화면이 보여 준다)*

이진: 정답은 필수, 예측과 양성 확률(score) 중 하나는 필수. 확률이 있어야 AUROC 같은 곡선 지표를 쓸 수 있다. latency\_ms는 선택.

```csv
id,y_true,y_pred,score,latency_ms
S001,1,1,0.91,12
S002,0,1,0.62,9
S003,0,0,0.08,11
```

다중 클래스: 정답은 필수, 예측과 클래스별 확률(prob\_클래스명) 중 하나는 필수. 확률만 있으면 가장 높은 클래스를 예측으로 쓴다.

```csv
id,y_true,y_pred,prob_cat,prob_dog,prob_bird
S001,cat,cat,0.81,0.12,0.07
S002,dog,bird,0.10,0.35,0.55
S003,bird,bird,0.05,0.15,0.80
```

멀티레이블: 레이블은 | 로 구분하고, 빈칸은 레이블 없음이다. 정답은 필수, 예측과 레이블별 점수(score\_레이블명) 중 하나는 필수.

```csv
id,true_labels,pred_labels,score_sports,score_news
S001,sports|news,sports,0.92,0.41
S002,news,news,0.08,0.88
S003,,news,0.12,0.57
```

### ② 지표와 합격 기준 (필수)

평가 지표와 목표 기준.

| 필드 | 입력 예시 | 구분 |
| --- | --- | --- |
| 지표 | 선택한 분류 유형에서 고를 수 있는 지표 중 선택 (최소 1개) | 필수 |
| 합격 기준 | `Accuracy ≥ 0.85` (혼동행렬은 면제) | 필수 |
| β | `1.0` | Fβ 선택 시 |
| 지표 선택 이유 | `오차를 고르게 봄 / 모든 레이블 일치 / 겹치는 정도 / 기타(직접 입력)` | 필수 (멀티레이블만) |
| 핵심 지표 | `Accuracy · F1` (유형별 기본값을 미리 체크) | 필수 (최소 1개) |

카드에 **고를 수 있는 지표 보기** 버튼을 두고, 선택한 분류 유형의 지표만 보여준다. *(MATERIAL_PICKER.md로 대체됨, §4 — 재료 고르기에는 보기 버튼이 없다)*

핵심 지표는 Details 의 합격 기준 표에서 목표값 옆 체크칸으로 고른다. 판정이 목표값과 함께 정해지기 때문이다. 유형별 기본값(이진·다중 클래스 Accuracy·F1, 멀티레이블 F1·Jaccard)이 미리 체크돼 있다. 핵심 지표가 목표에 미달하면 최종 불합격이고, 그 밖의 지표가 미달하면 조건부 합격이고, 핵심 지표가 산출되지 않았거나 판정 대상이 없으면 판정 불가다(서술 설계 D19). 목표값이 있는 지표가 있으면 최소 1개를 골라야 넘어갈 수 있다(재료 목록 7절). 성적서 시험 결과 표에는 핵심 지표에 "핵심" 표시가 붙고, 6.1 표 아래에 판정 규칙(고정 문구 10)이 찍힌다. *(MATERIAL_PICKER.md로 대체됨, §5 — 합격 기준 표는 지표와 합격 기준 화면으로 옮겼다)*

| 분류 유형 | 고를 수 있는 지표 |
| --- | --- |
| 이진 (15개) | M1 Accuracy, M2 Precision, M3 Recall, M4 F1, M5 Fβ, M6 KL Divergence, M7 Specificity, M8 FPR, M9 AUROC\*, M10 AUPRC\*, M19 Log Loss\*, M20 MCC, M21 혼동행렬, M22 클래스별 지표, M23 불균형 비율 |
| 다중 클래스 (13개) | M1 Accuracy, M2 Precision, M3 Recall, M4 F1, M5 Fβ, M6 KL Divergence, M11 Macro 평균, M12 Micro 평균, M13 Weighted 평균, M14 분포 차이, M21 혼동행렬, M22 클래스별 지표, M23 불균형 비율 |
| 멀티레이블 (11개) | M2 Precision, M3 Recall, M4 F1, M5 Fβ, M15 Hamming Loss, M16 Exact Match, M17 Jaccard, M18 분포 차이, M21 혼동행렬, M22 레이블별 지표, M23 불균형 비율 |

\* 확률(score) 컬럼이 있어야 고를 수 있다. 확률 컬럼을 매핑하지 않았으면 지표 화면에서 이유와 함께 비활성으로 보인다(MATERIAL_PICKER.md §3).

멀티레이블에서는 M1 Accuracy를 고를 수 없다. TS 4213 6.5.1은 멀티레이블에서 정확한 일치율을 "이진 정확도를 조정한 것"으로, 6.5.3은 이를 "서브 세트 정확도"로 정의하므로 멀티레이블의 Accuracy는 M16 Exact Match와 같은 값이다. 백엔드도 같은 이유로 멀티레이블에서 M1·M11·M12·M13을 노출하지 않는다(app/core/schemas.py, 2026-09-07 결정 2).

### ③ 의뢰자 정보 (필수)

성적서를 받는 회사와 용도.

| 필드 | 입력 예시 | 구분 |
| --- | --- | --- |
| 회사 정보 | `(주)테스트기업 · 홍길동 · 123-45-67890 · 02-1234-5678 · 서울시 …` | 필수 |
| 성적서 용도 | `내부 검증 / 외부 제출 / 과제 제출` | 필수 |

더보기: 홈페이지·팩스, 과제 번호, 평가 의뢰일 (기본 오늘)

### ④ 평가 대상 모델 (필수)

모델 이름과 쓰임새.

| 필드 | 입력 예시 | 구분 |
| --- | --- | --- |
| 모델 이름·버전 | `ChurnPredictor · v1.0.0` (버전 기본 v1.0.0) | 필수 |

### ⑤ 평가 관점 (필수)

이 모델에서 무엇을 중요하게 볼지. 필드는 분류 유형에 따라 다르며, 사용자는 항상 두 개를 받는다.

| 필드 | 입력 예시 | 구분 |
| --- | --- | --- |
| 중요 오류 유형 | `놓침(FN) / 잘못 잡음(FP) / 비슷함` | 필수 (이진) |
| 클래스 중요도 | `모두 동등 / 큰 클래스 우선 / 개별 샘플 우선` | 필수 (다중·멀티) |
| 사용 방식 | `실시간 응답 / 일괄 처리` | 필수 |

고른 지표가 답과 맞지 않으면 지표 화면의 "목적별 점검"과 검증 화면의 생성 전 안내에서 경고한다(진행은 막지 않는다). 판정은 재료 선택 점검 함수 하나(`src/lib/report/materialCheck.ts`, 점검 표 1.0)가 한다. 값은 성적서 5절에 인쇄되고 AI 서술의 기준이 된다.

| 필드 | 선택지 | 확인하는 것 | 근거 (TS 4213) |
| --- | --- | --- | --- |
| 중요 오류 유형 | 놓침(FN) | Recall 또는 β가 1보다 큰 Fβ를 골랐는가 | 6.2.6 |
| 중요 오류 유형 | 잘못 잡음(FP) | Precision 또는 β가 1보다 작은 Fβ를 골랐는가 | 6.2.6 |
| 중요 오류 유형 | 비슷함 | 확인 없음 | 6.2.6 |
| 클래스 중요도 | 모두 동등 | 매크로 평균 지표를 골랐는가 | 6.4.3 |
| 클래스 중요도 | 큰 클래스 우선 | 가중 평균 지표를 골랐는가 | 6.4.3 |
| 클래스 중요도 | 개별 샘플 우선 | 마이크로 평균 지표를 골랐는가 | 6.4.3 |
| 사용 방식 | 실시간 응답 | 응답시간(latency) 컬럼을 매핑했는가 | 6.6.2 |
| 사용 방식 | 일괄 처리 | 확인 없음 | 6.6.2 |

다중 클래스의 Accuracy는 마이크로 평균 지표로 인정하고, 클래스별 지표(M22)를 고르면 세 평균 방식이 모두 있는 것으로 본다. 멀티레이블은 모두 동등이면 Precision·Recall·F1·Fβ·M22, 나머지 둘은 M22만 인정한다. 위 표 밖에 한 줄이 더 있다: 이진에서 곡선 지표(AUROC·AUPRC)를 골랐고 불균형 비율이 9를 넘으면 AUPRC가 있어야 한다(6.3.6·6.3.7).

학습 데이터 설명·비고는 성적서 학습 데이터 절에 인쇄된다. 종전에는 Details 의 "Report notes"(평가에 대한 메모)가 이 자리에 "학습 데이터 설명"으로 찍혔다. 그 칸은 없앴다. 전처리 자유서술 칸은 없애고 ⑦ 의 "학습과 같은 전처리" 한 칸으로 바꿨다(서술 설계 D44).

## 카드별 입력 단계

> **MATERIAL_PICKER.md로 대체됨** (§3·§5) — 매핑이 지표에 기대지 않게 되면서(유형 기준 필수 역할만 막고, `/api/confirm-mapping` 은 빈 지표 목록을 받는다) 검증 앞도 카드 순서를 따른다. 순서는 의뢰자 정보 → 평가 대상 모델 → [모델 설정과 실행 환경] → 평가 데이터 → 컬럼 매핑 → [데이터 정보] → 평가 관점 → 지표와 합격 기준 → 검증 → 확인과 생성이고, 최소 8단계·전체 10단계다(§11로 대체됨 — 데이터 카드가 단계마다 나뉘어 전체 12단계이고, 순서는 사용자가 정한다). 의뢰자 정보·데이터 정보·모델 설정과 실행 환경은 run 앞이라 `/app/*` 경로다. 합격 기준과 핵심 지표는 지표와 합격 기준 화면이 받고, 실행 환경은 ⑨ 하나로 받는다. 아래는 종전 기록.

구성 화면에서 고른 카드는 아래 단계에 매핑된다. 카드는 "성적서에 무엇이 들어가는가", 단계는 "언제 묻는가"라서 한 카드가 두 단계에 나뉘기도 한다(①, ②, ④).

> 2026-10-05 개정(WORKFLOW\_REDESIGN §11). 고객이 시험 기관이라 "평가만 하는 사용자"가 없다. 평가 결과 단계를 없애고, 검증 뒤를 구성 화면의 카드 순서로 맞췄다. 평가 관점은 그 전에 지표 선택 화면 안으로 들어갔다(§10.1).

| 단계 | 단계 이름 | 받는 카드·필드 | 나타나는 조건 |
| --- | --- | --- | --- |
| 1 | Evaluation File | ① 결과 파일, ④ 모델명·버전 | 항상 |
| 2 | Metrics | ⑤ 전체(화면 맨 위), ② 지표·β·지표 선택 이유 | 항상 |
| 3 | Column mapping | ① 컬럼 매핑, 양성 클래스, 결정 임계값 | 항상 |
| 4 | Validation | — (검증 후 run 저장) | 항상 |
| 5 | Details | ③ 전체, ④ 모델 용도, ② 합격 기준·핵심 지표 | 항상 |
| 6 | Data info | ⑥ ⑦ ⑧ 중 켠 카드(카드 순서대로) | 셋 중 하나라도 켰을 때 |
| 7 | Model info | ⑨ 전체 | ⑨를 켰을 때 |
| 8 | Result | — (평가 실행, AI 서술, 성적서) | 항상 |

최소 구성이면 6단계(1\~5, 8), 전체면 8단계가 된다.

순서는 다음 이유로 정했다.

- **검증 뒤는 카드 순서를 따른다.** ③ 의뢰자 정보 → ⑥ ⑦ ⑧ → ⑨ 순서다. 선택 카드를 어떻게 조합해도 켠 카드의 단계가 카드 순서대로 나오고, 필수 카드의 단계보다 뒤에 온다. 코드에서는 `workflowSteps.test.ts` 의 "카드 순서" 테스트가 16가지 조합 전부를 확인한다.
- **검증 앞의 필수 카드는 카드 순서를 따를 수 없다.**
  - 지표가 매핑보다 앞인 것은 백엔드가 지표 목록 없이 검증·평가 요청을 받지 않기 때문이다(WORKFLOW\_REDESIGN §2.1). 그래서 ① 이 업로드와 매핑으로 갈린다.
  - ⑤ 평가 관점은 지표 점검의 기준이다. 지금은 지표 화면 바로 앞 단계다(MATERIAL_PICKER.md §3). 지표 화면이 이 답으로 목적별 점검을 보여 준다.
- **검증을 성적서 입력 앞에 둔다.** 파일·매핑 오류를 의뢰자 정보를 적기 전에 알 수 있다. 실제 평가 API 는 모든 입력을 마친 Result 에서 처음 불리므로, 여기서 받은 값이 성적서와 AI 서술에 모두 들어간다.
- ⑥ 의 학습 클래스 분포는 매핑에서 확정한 클래스 목록이 필요하다. Data info 는 항상 매핑 뒤라 이 제약이 자연히 지켜진다.
- **재료 선택 점검은 검증 화면의 "다음"에서 실행**한다(성적서 생성 직전, 모든 입력이 확정된 때). 1층 빈칸은 막고, 2·3층 경고는 기록하고 진행한다. 지표 화면은 같은 점검의 3층 줄을 미리 보여 준다.

## 구성 화면 레이아웃

> **MATERIAL_PICKER.md로 대체됨** (§4) — 3단이다: 왼쪽 대분류 네모 카드와 카드 목록, 가운데 필드(필수/권장/선택/조건부)와 저장, 오른쪽 입력 순서와 "필수 5개 중 N개 저장"·이전/다음. 아래는 종전 기록.

세부 디자인(폰트, 색, 크기)은 다음 단계에서 정하고, 여기에는 배치만 둔다.

1. **맨 위**: 선택한 분류 유형 표시, 화면 제목 "성적서 구성", 프리셋 버튼(최소 구성 / 전체)
2. **필수 카드 줄**: ①\~⑤를 한 줄에 가로로 놓는다. 자물쇠 표시, 끌 수 없다.
3. **선택 카드 줄**: ⑥\~⑨를 그 아래 한 줄에 가로로 놓는다. 왼쪽 위 체크박스로 켜고 끈다(기존 Selectable Card와 같은 위치).
4. **상세 영역**: 카드를 누르면 카드 줄 아래 여백에 그 카드의 설명과 필드 표가 나온다. 한 번에 한 카드만 보이며, 화면에 들어오면 ①이 선택된 상태로 시작한다. ①에는 예시 파일 보기, ②에는 고를 수 있는 지표 보기 버튼을 둔다.
5. **하단 바**: 요약 한 줄(분류 유형 · 선택 카드 n/4 켜짐 · 입력 단계 n개)과 다음 버튼.

카드를 **누르는 것**(상세 보기)과 **켜는 것**(체크박스)은 분리한다. 합치면 내용을 보려고 눌렀다가 카드가 꺼지는 일이 생긴다. 하단 요약은 레지스트리에서 계산하며 AI 호출이나 서버 요청은 없다.

## 결정 사항과 열린 결정

**프리셋은 "최소 구성"과 "전체" 두 가지로 한다.** 최소 구성은 필수 카드 5개만, 전체는 필수 5개와 선택 4개를 모두 켠다. 더보기 필드는 프리셋과 무관하게 입력 단계에서 펼쳐 쓸 수 있다. *(MATERIAL_PICKER.md로 대체됨, §4·§7 — 프리셋은 없앴다. 카드마다 골라 저장한다)*

**⑤ 평가 관점은 구성 화면이 아니라 입력 단계(2단계)에서 받는다.** 질문이 늘어날 수 있어 구성 화면에 두면 화면이 무거워진다. *(MATERIAL_PICKER.md로 대체됨, §3 — 지표와 합격 기준 바로 앞의 단독 단계다)*

평가 관점은 사용자가 선택지로 답하는 **고정 질문**이다. AI가 만드는 질문이 아니고, 모델마다 달라지지도 않는다. 분류 유형에 따라서만 달라진다.

질문은 늘어날 수 있지만, 새 질문은 두 가지를 갖춰야 한다. TS 4213의 근거 조항이 있어야 하고, 그 답이 요구하는 재료(점검 줄, 예: "대화형이면 지연시간 필요")가 정해져야 한다. 점검에 쓰이지 않는 질문은 평가 관점이 아니라 일반 입력 필드다.

남아 있던 열린 결정도 정했다.

- [x] **선택 카드를 켠 뒤 보고 필드를 비운 채 진행할 수 있는지.** 예를 들어 ⑧ 정답 라벨을 켜고 구축 방법만 고른 채 신뢰성을 비워 두는 경우다. 결정: 비운 채로는 진행할 수 없다. 켠 카드의 표준 보고 필드는 반드시 입력해야 하고, 모르면 "모름"을 골라야 한다. "모름"은 성적서에 "제공되지 않음"으로 찍힌다. 카드를 끄는 것은 여전히 허용된다. *(MATERIAL_PICKER.md로 대체됨, §6 — 권장 항목은 골라 저장한 것만 받는다. 받기로 한 항목은 비울 수 없고 모르면 "모름"을 고른다)*

## 구현 메모

**재료 레지스트리를 먼저 만든다.** 재료 목록 문서를 코드가 읽는 설정 파일 하나로 옮긴 것으로, 항목마다 소속 카드, 입력 방식, 구분, 적용 유형, 성적서 위치, AI 전달 여부를 담는다. 구성 화면의 카드, 하단 요약, 입력 단계 생성, 재료 선택 점검, 성적서 렌더링이 모두 이 파일 하나를 읽는다. 단계 목록도 고정 번호(현재 `STEP` 상수)가 아니라 선택 결과에서 계산한다.

현재 구현과 달라지는 점은 다음과 같다(재료 목록의 구현 상태 기준).

| 항목 | 현재 | 바꿀 것 |
| --- | --- | --- |
| ⑤ 평가 관점 전체 | 설계만 | 새로 만든다 |
| ⑦ 테스트 데이터 전체 | 설계만 | 새로 만든다 (데이터 출처는 재료 목록대로 한 줄 텍스트) |
| ⑧ 정답 라벨 전체 | 설계만 | 새로 만든다 |
| ⑥ 수집 환경 차이, 불균형 보정 | 설계만 | 새로 만든다. 수집 환경 차이는 복수 선택 + 기타 직접 입력 |
| ⑥ 수집 기간, 전처리 여부 | 재료 목록에 없음 (이번에 새로 추가) | 재료 목록 문서에 추가하고 새로 만든다. 전처리 여부는 직접 입력 |
| ⑦ 전처리, 전처리 내용 | 없음 (2026-10-06 지도교수 피드백으로 추가) | 레지스트리에 추가함. 학습과 같은지는 선택지, 내용은 직접 입력. 둘 다 선택(더보기) |
| ⑨ 하이퍼파라미터, GPU 사용 여부 | 설계만 | 새로 만든다 |
| ⑥ 데이터 이름·데이터 양 | 필수 입력, AI에 안 감 | 선택 카드 안의 필드로 바꾸고 AI에 넘긴다 |
| ⑥ 클래스별 데이터 양 | 자유서술 | 클래스마다 숫자로 받는다 |
| ⑥ 검증 데이터 양 | 평가 표본 수 칸에도 인쇄되는 버그 | 버그를 고친다 |
| ⑨ 실행 환경 | AI에 안 가고 빠져도 경고 없음 | AI에 넘기고 빠지면 "제공되지 않음"으로 표시한다 |
| ④ 모델 이름·버전, 모델 용도 | AI에 안 감 | AI에 넘긴다 |
| ① 결과 파일 예시, ② 지표 목록 보기 | 없음 | 분류 유형별 버튼으로 새로 만든다 |
| ② 핵심 지표 | 코드 상수, 고르는 화면 없음 | Details 합격 기준 표에서 고른다. 기본값은 그 상수다. 판정과 성적서 "핵심" 표시에 쓴다 (2026-10-06 입력 화면 점검) *(MATERIAL_PICKER.md로 대체됨, §5 — 지금은 지표와 합격 기준 화면에서 고른다)* |
| ② 지표 선택 이유 | 정의만 있고 화면 없음 | 지표 화면 격자 아래에서 받는다(멀티레이블). 기타는 직접 입력 |
| ⑥ 학습 데이터 설명·비고 | 칸 없음. Details "Report notes" 가 "학습 데이터 설명"으로 인쇄됨 | ⑥ 에 두 칸을 만들고 성적서에 인쇄한다. Report notes 칸은 없앴다 |
| ⑥ 불균형 보정 | 하나 고르기, 기타 없음 | 복수 선택 + 기타 직접 입력. "보정 안 함"은 배타 |
| ⑥ 수집 환경 차이 | 기타를 골라도 적을 칸 없음 | 기타를 고르면 칸이 나타나고 필수가 된다 |
| ⑥ ⑦ 수집 기간 | 자유 텍스트 한 칸 | 시작 월·끝 월 두 칸, 순서 검사 |
| ⑧ 라벨 작성 주체 | 기타 없음 | 기타(직접 입력)를 더해 다섯 가지 |
| ⑧ 검수 인원·일치율 | 자유 텍스트 한 칸 | 라벨러 수(1 이상 정수)와 일치도 종류 + 값. 범위는 종류를 따르고, 라벨러 수와 맞지 않는 카파는 막는다(D42) |
| ⑥ ⑦ 전처리 세 칸 | 자유서술 세 칸(⑥ 1개, ⑦ 2개) | ⑦ "학습과 같은 전처리" 한 칸(같음 / 다름 / 모름 + 덧붙이는 글)으로 바꿈(D44) |
| ⑥ 학습 데이터 출처·수집 기간 | 재료 목록에 없음 | 재료 목록에 더함. 출처는 2층, 수집 기간은 점검 밖(D43) |
| Details 학습 데이터셋 폼 | ⑥ 과 같은 값을 따로 받고 성적서는 그쪽만 읽음 | 폼을 없애고 ⑥ 하나로 합침. 성적서는 ⑥ 값을 읽음(persist v10) |

2026-10-14 부터 성적서 구성 카드의 값은 재료 목록의 인쇄 위치대로 성적서에 찍히고 AI 에도 간다(`lib/report/reportMaterials.ts`). 2층 항목이 빠지면 "제공되지 않음"으로 찍는다. 다만 화면에서 2층 항목이 카드를 켜면 필수가 되는 것(재료 선택 점검의 "경고만 하고 진행")은 아직 그대로다. *(MATERIAL_PICKER.md로 대체됨, §6 — 재료 고르기에서 권장 항목을 고르게 됐다. 입력 화면 쪽은 PR4)*
